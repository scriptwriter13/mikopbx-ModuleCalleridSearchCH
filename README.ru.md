# О модуле
Модуль для MikoPBX, который при входящем звонке показывает имя звонящего из телефонного справочника
Швейцарии [tel.search.ch](https://tel.search.ch).

При каждом входящем звонке номер ищется в справочнике, и в имя CallerID подставляется строка вида
`Фамилия И. Город, Улица 1`. Номер может приходить как `044…`, `+4144…`, `004144…` или `4144…`.
Номера не из Швейцарии и номера, которых нет в справочнике, остаются без изменений,
поэтому имя, переданное провайдером, не теряется.

# Установка

**Обновление с предыдущих версий:** Сначала удалите старый модуль `CalleridSearchCH`. 
Идентификатор модуля теперь получил префикс Module, требуемый MikoPBX. Установка поверх старой версии 
приводит к тому, что оба модуля остаются активными, из-за чего при каждом входящем вызове для каждого 
активного модуля выполняется отдельный поиск, а старый скрипт продолжает работать.


1. Соберите архив модуля (см. ниже) или возьмите его на странице релизов.
2. В админ-панели MikoPBX откройте Модули → Установленные → Загрузить новый модуль и выберите zip-файл.
3. Включите модуль.
4. Откройте страницу модуля, вставьте ключ API и нажмите «Сохранить».
5. При необходимости вы также можете вмешаться в процесс обработки вызовов. Изменяйте эти настройки 
только в том случае, если вы полностью уверены в своих действиях. Здесь можно отклонять анонимные 
вызовы или вызовы категории «колл-центр». Также при желании можно предварительно воспроизвести 
записанное пользователем объявление перед завершением вызова.

Требуется MikoPBX 2025.1.1 или новее.

## Ключ API

Ключ выдаётся на https://tel.search.ch/api/getkey, при умеренном использовании он бесплатен.
Без ключа справочник возвращает только имя, без города и улицы.

На странице модуля можно с помощью галочек выбрать, нужно ли отклонять анонимные звонки или звонки категории колл-центр.

# Конфиденциальность

Номер звонящего при каждом входящем швейцарском звонке передаётся в tel.search.ch по HTTPS.
Модуль ничего не хранит о звонках и не ведёт журнал имён и адресов.

## Режим кодирования (Транслитерация CallerID)
Для обеспечения полной совместимости с различными моделями IP- и аналоговых телефонов в настройках модуля предусмотрен выпадающий список «Режим кодирования» (Encoding Mode) с взаимоисключающими опциями. Вы можете выбрать один из следующих вариантов:

* **Стандарт (UTF-8 / Без конвертации)** (`none`)  
  * *Описание:* Передает символы без изменений в кодировке UTF-8. Наилучшим образом подходит для современных IP-телефонов, которые поддерживают юникод «из коробки».
* **Преобразование специальных символов** (`ascii`)  
  * *Описание:* Конвертирует специальные символы и умлауты (например, `ö` -> `oe`, `ä` -> `ae`) в стандартные символы ASCII. Идеально подходит для старых IP-телефонов с ограниченной поддержкой символов.
* **Принудительный швейцарский ISO-646-CH** (`iso646ch`)  
  * *Описание:* Применяет историческую кодировку швейцарского стандарта ISO-646-CH. Специально для старых швейцарских телефонных станций и совместимых абонентских устройств.
* **ISO-8859-1 (Latin-1)** (`iso88591`)  
  * *Описание:* Использует классическую западноевропейскую кодировку ISO-8859-1. Рекомендуется для старых цифровых системных телефонов и уставшего «железа».

# Решение проблем

- На весь запрос к справочнику отводится жёсткие 2 секунды. Если он не ответил, звонок
  продолжается с исходным CallerID.
- Сбои не замалчиваются и не рвут звонок: причина пишется в лог Asterisk через AGI verbose с
  префиксом `CalleridSearchCH:`. Отклонённый или исчерпанный ключ видно там же. Имена и адреса
  звонящих в лог не попадают.
- Имя не показывается: сначала посмотрите лог Asterisk, затем проверьте, что у номера есть
  публичная запись на tel.search.ch.
- Самопроверка без АТС и сети: `php tests/LookupTest.php`
